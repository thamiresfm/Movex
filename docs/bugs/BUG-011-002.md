## Descrição

A função `renderLogs()` em `Logs.ts` usava `el.innerHTML` para injetar entradas de log diretamente no DOM sem escapar o conteúdo. O campo `e.msg` era controlável por dados vindos do backend (hostname do peer, erros de rede), tornando possível injeção de HTML/JavaScript.

---

## Passos para reproduzir

1. Servidor malicioso anuncia hostname com conteúdo HTML (ex: `<img src=x onerror=alert(1)>`)
2. Cliente Movex conecta-se ao servidor
3. `onStatusChange` emite log com o hostname
4. `renderLogs()` injeta o HTML diretamente via `innerHTML`
5. Script arbitrário executa no contexto da webview Tauri

---

## Comportamento esperado

Mensagens de log devem ser exibidas como texto simples; qualquer HTML no conteúdo deve ser escapado.

---

## Comportamento observado

HTML no campo `msg` era renderizado pelo browser engine da webview.

---

## Causa raiz

`Logs.ts:21` — template literal com `${e.msg}` inserido em `el.innerHTML` sem `esc()`.

---

## Correção aplicada

`src/components/Logs.ts`:
- `renderLogs()` reescrita com `document.createDocumentFragment()` e `document.createElement()`
- Todos os campos (`e.time`, `e.level`, `e.msg`) atribuídos via `.textContent`
- `el.replaceChildren(fragment)` substitui `el.innerHTML`
