## Descrição

A função `verify_hmac` em `auth.rs` usava `unwrap_or_else(|_| psk_hex.as_bytes().to_vec())` ao decodificar a PSK de hexadecimal. Se a PSK não fosse hex válido, o código silenciosamente usava os bytes literais da string hex como chave HMAC — um comportamento diferente de `compute_hmac` (que retornava `Err`). Isso criava uma inconsistência que poderia resultar em falsos positivos ou negativos na verificação.

---

## Passos para reproduzir

1. Configurar PSK com caracteres não-hex (ex: `zzzz...`)
2. `compute_hmac` retorna `Err` → cliente não envia Hello
3. `verify_hmac` com mesma PSK usava bytes literais como chave — não detectava o erro

---

## Comportamento esperado

`verify_hmac` deve retornar `false` se a PSK não for hexadecimal válido, consistente com `compute_hmac`.

---

## Causa raiz

`auth.rs:26` — `.unwrap_or_else(|_| psk_hex.as_bytes().to_vec())` mascarava erros de parse.

---

## Correção aplicada

`src-tauri/src/core/auth.rs`:
- Substituído por `match hex::decode(psk_hex) { Ok(b) => b, Err(_) => return false }`
- Comportamento agora consistente: PSK inválida → `false` imediato
